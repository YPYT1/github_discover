一个使用真实 GitHub 数据的开源项目发现网站，基于 Next.js、Cloudflare Workers 与 D1。

**当前不需要 Cloudflare 密钥即可本地开发。项目尚未部署；真实 OAuth、远程 D1 与 Cron 需要配置后联调。** PAT 只在浏览器保存；OAuth Token 在服务端加密保存，两种登录方式的存储规则不同。

## 本地启动

使用 Node.js 22 或更新的受支持 LTS 版本及 pnpm 11+。

```powershell
pnpm install
Copy-Item .dev.vars.example .dev.vars
pnpm db:migrate:local
pnpm dev
```

打开 http://localhost:3000。公开搜索无需登录，GitHub API 在无服务端 Token 时有更严格的限流。数据库位于 `.wrangler/state/`，不要提交该目录。

`.dev.vars` 中的 `APP_URL` 必须与访问地址完全一致，包括协议、域名和端口。它用于 OAuth 回调及写操作的 Origin 检查。若 Next.js 切换到 3001，请同步修改配置并重启。

## 登录与令牌存储

### 个人访问令牌登录

点击登录按钮，填写自己的 GitHub PAT。无需配置 GitHub OAuth App。

- PAT 只保存于当前浏览器的 `localStorage.discover_pat`，**不写入 D1、Cookie 或服务端会话数据**。
- PAT 登录与需要用户 GitHub 权限的请求会临时将令牌发送到本站服务端，再由服务端校验/转发给 GitHub。线上必须使用 HTTPS；本地 HTTP 仅用于开发。
- 每次使用 PAT 调用用户 GitHub API，服务端验证令牌所属 GitHub ID 与数据库会话用户一致。
- D1 保存用户公开资料、独立会话 ID 的哈希、语言/主题、收藏、浏览历史和兴趣屏蔽记录。
- 退出成功后，浏览器清除 PAT，数据库撤销对应会话。
- 浏览器本地令牌会受到同源脚本、浏览器扩展及设备访问者的影响，请仅在可信设备使用。服务端或反向代理不得记录请求体或 `x-github-token` 请求头。

细粒度令牌读取公开信息不需要私人仓库权限，写入 Star 需要用户权限 **Starring: read and write**；读取自己的关注列表可能需要 **Followers: read**。经典令牌写入 Star 需要 `public_repo`，这个权限范围较宽。实际可用权限以 GitHub 令牌设置页面为准。

### OAuth 登录

在 GitHub 创建 OAuth App，本地回调地址设置为：

```text
http://localhost:3000/api/auth/callback
```

填写 `.dev.vars` 中的 `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET` 与 `TOKEN_ENCRYPTION_KEY`。生成独立的 32 字节加密密钥：

```powershell
pnpm exec node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

基础 OAuth 登录不主动请求私人仓库访问权限。写 Star 的额外授权是可选操作，需要 GitHub OAuth App 的 `public_repo` 范围；GitHub 未提供只写 Star 的 OAuth App scope，界面会说明其较宽权限。

OAuth Token 以 AES-GCM 加密后保存在 D1；解密密钥必须作为 Worker Secret 保存。不要随意更换加密密钥，否则已存 Token 无法解密，用户需重新登录。会话 Cookie 为 HttpOnly、SameSite=Lax，线上启用 Secure，默认 30 天有效。

## 已实现功能

- GitHub Primer 风格，浅色/深色/跟随系统。
- English、简体中文、한국어、日本語、Русский；匿名用户 cookie，登录用户偏好保存到 D1。
- 基于容器实际空间的 1–4 列瀑布流。卡片最小宽度 260px，间距 16px，最大页面宽度 1560px；窄手机单列，空间足够时双列。
- 双层仓库卡片、GitHub 原始介绍、Star/Fork、Topics、许可证和本地化日期；语言数据仅在真实获取到时显示。
- 搜索、语言/Topic 分类、排序、最低 Star、许可证、创建与更新时间筛选、URL 状态、`/` 搜索快捷键。
- 无限加载与手动加载按钮；追加数据不移动已有卡片。屏幕宽度改变时允许重新排版。
- 桌面右侧详情 Drawer、移动全屏详情；关闭/浏览器返回保留已加载列表与滚动位置。
- PAT/OAuth 登录、数据库收藏、浏览历史、偏好屏蔽、个人 Stars、关注开发者的公开仓库、GitHub Star 读写和分享。
- 仓库/搜索缓存、历史 Star 快照、每 6 小时 Cron 采集。

## 数据范围与限制

- **不提供伪造数据兜底**：GitHub 超时、限流、权限不足时显示可重试错误。
- GitHub 搜索最多允许访问前 1,000 条结果。公开搜索每页 25 条，缓存 5 分钟；搜索分页在本站使用不透明游标封装上游页码，不是 GitHub 的原生游标。
- 分类基于公开 Topic 映射，不是人工审核的完整分类库；个性化推荐规则见下方。不是训练的机器学习模型，不承诺全 GitHub 最优排名。
- Latest 默认寻找最近 90 天创建的仓库。GitHub 仓库搜索不支持按创建时间排序，因此抓取最多 300 个近期活跃的匹配候选，再按实际创建时间排序，不代表全 GitHub 完整新仓库排名。
- Trending 仅对本站已采样的项目计算日/周/月 Star 增量。新数据库没有相应基线时明确展示“等待历史快照”，不将更新时间当成热度。
- 收藏和历史展示最近 1,000 个记录；D1 中的其余记录不会删除。个人 Stars 最多读取 500 个仓库；Following 最多读取关注列表的前 20 位开发者，每人最近更新的 10 个公开仓库，并不等于完整 GitHub Events 动态。
- 个人列表及历史快照趋势使用文本匹配；GitHub 限定符语法适用于公开 GitHub 搜索信息流。
- Contributors 与 Languages 在详情读取时向 GitHub 查询，未取得的数据不显示。没有从 README 自动猜测 Logo，使用真实所有者头像。
- 收藏与 Star 的状态需详情接口加载成功才可信；真实账户授权及写操作仍需使用实际账户联调。

## 检查

### 个性化推荐与曝光去重

“为你推荐”无主动搜索且为推荐排序时：语言/Topics 技术栈匹配 + 收藏/详情反馈 + 时间衰减 + 新鲜度 + 中小项目探索 + 作者/技术方向多样性。OAuth 和 PAT 均可使用最多 100 个最近 Star 与 100 个公开自有仓库建立画像（缓存 30 分钟）；权限不足时仍可使用站内信号。私人仓库不会进入画像缓存，PAT 不持久化。

每次刷新生成新的随机推荐批次，多路召回中小型、近期活跃、新建和匹配技术栈的候选，不以总 Star 主导；知名仓库降权，每五个排序位置增加探索权重。候选搜索在前 3 页轮换，共享缓存 15 分钟，结合最近 1,500 个真实仓库缓存，每批最多 600 个候选，分页快照保持 1 小时。探索权重不是固定配额，也不是无限候选源。

卡片至少 50% 可见持续 1 秒（后台标签页/打开详情遮挡时不计时），或打开详情即记为已看。曝光本身不计为喜欢，也不会填充浏览历史。当前页面保留卡片，后续推荐排除；搜索、显式排序、其他列表不受限制。登录用户按账户保存在 D1，无仓库外键以免缓存删除导致去重丢失；本地重试队列每 5 秒同步，失败会提示，未成功同步前无法保证跨设备去重。匿名用户保存在当前浏览器；清理浏览器数据会清除匿名记录。

匿名记录不自动合并到登录账户。浏览器记录不定时过期，请求最多发送最近 10,000 个 ID，客户端仍检查完整本地记录，绝不展示被截断的旧已看项目。推荐候选耗尽时明确提示，不回收已看项目。

```powershell
pnpm exec tsc --noEmit
pnpm lint
pnpm test
pnpm build
pnpm cf:build
pnpm format:check
```

浏览器自动检查需先启动 `pnpm dev`，并安装 Google Chrome：

```powershell
pnpm test:ui
```

UI 脚本使用明确的测试专用网络 fixture 检查布局/交互，不验证真实 OAuth 或 GitHub 写操作，生产代码不使用这些 fixture。覆盖六种宽度、稳定追加、详情关闭、主题、PAT 存储说明、空/错误状态和语言切换。截图位于 `output/playwright/`。

启动 `pnpm preview` 后执行 `pnpm test:worker`，验证真实编译 Worker 的 HTTP 路由、首页 SSR、本地 D1 和定时接口认证，不使用 UI fixture。此命令能发现“构建成功但 Worker 无法加载”的错误。

`patches/@opennextjs__cloudflare@1.20.9.patch` 修复适配器遗漏 Next.js 16.4 的 `preview-props.json`：复制并内联真实构建清单，不伪造预览密钥。pnpm 安装会自动应用版本固定的补丁；升级 OpenNext 后先确认上游是否已修复，并重新运行 Worker 测试。

Windows 下运行 `pnpm cf:build` / `pnpm preview` 前，先关闭已有的 Next.js dev 和 Workers preview 服务，避免 `.open-next` 被本地绑定模拟器占用导致 EPERM。

Next.js、React、Tailwind、ESLint 和 OpenNext 使用安装时稳定版。TypeScript 固定为 6.x，以兼容当前 typescript-eslint；升级需同时验证 typescript-eslint 与 Next.js ESLint 插件。部分 ESLint 插件的 peer 范围尚未声明 ESLint 10，当前实际 Lint 检查通过。Miniflare 测试使用稳定 4.x（Hub 的 latest 标签指向 alpha，不使用该版本）。pnpm 使用 hoisted 布局，避免 Windows 下 OpenNext 复制 pnpm 链接后无法打包的问题。

参见 [Cloudflare 部署说明](Cloudflare部署.md)。暂不要直接运行 `pnpm deploy`，先创建 D1、填写真实 database ID 与域名、配置 Worker Secrets，再执行远程迁移。

## 项目入口

- `src/app/`：页面与 API 路由。
- `src/components/feed/`：搜索/筛选、分页与瀑布流。
- `src/components/repository/`：卡片、语言条、详情和仓库操作。
- `src/components/layout/`：导航、主题/语言、账户菜单与登录。
- `src/lib/`：GitHub 请求、数据库缓存、推荐/趋势、身份校验、加密。
- `src/messages/`、`src/i18n/`：五种语言及首次语言匹配。
- `migrations/0001_initial.sql`：D1 Schema。
- `worker.mjs`：复用 OpenNext fetch handler，添加 Cron handler。
- `tests/`：单元与真实本地 D1 集成测试。
