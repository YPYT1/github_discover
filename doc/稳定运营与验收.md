# 稳定运营与验收

在原有 Workers + D1 架构内加入访问保护、公共回源缓存、采集进度与聚合告警。没有购买服务或升级套餐。

**仍未接入**：生产专用采集 Token、外部告警接收渠道。日志归档是本地在线工具，不是服务器永久日志库；离线期间不能保证日志完整。免费 Worker CPU、D1 和 GitHub 额度仍可能限制可用性。

## 查看采集、历史基线与告警

项目目录运行：

```powershell
pnpm ops:status
```

本机 `.env` 必须已有 `CRON_SECRET`；工具通过 HTTPS 调用鉴权诊断端点。不要把秘密放进 URL 或公开 `.env`。

输出包括：

- `tokenConfigured`：生产端是否设置专用采集 Token，不是本地是否存在。
- `sync`：最新一次任务开始/结束时间、搜索进度、回访量、观测条数、安全失败分类。`snapshots` 是处理次数，可能含重复仓库；实际每日覆盖量看 `snapshotDays`。
- `lastSuccessAt`、`collectionOverdue`：最近成功采集是否超过八小时。失败结束时间不会冒充成功时间。首次部署状态表、尚未执行新 Cron 时也会显示待采集。
- `coverage`：今天有真实观测、目标日附近有基线的仓库数，对应 1/7/30 天。不是全 GitHub 覆盖率或过滤后 feed 结果数。
- `alerts`：固定类别的聚合告警，含首次/最近时间、次数和解除时间。不保存访问日志、Token 或搜索词。

诊断使用已有 `/api/internal/sync` 的 GET；POST 才执行采集。两者均需 `CRON_SECRET`，看状态不应反复触发 POST。

## 真实趋势如何形成

每六小时 Cron 进行四组真实搜索，回访最多四十个最久未更新的已知仓库。网络/上游失败最多重试一次，配额或认证失败不重试；十分钟过期租约防重叠，回访阶段超过四分钟会停止并记录失败。部分失败保留已经取得的真实观测，不伪称全部完成。

只写真实观测日：缓存的观测时间跨午夜仍保留原日期，过期缓存降级不写今日 Star 快照。旧值不能覆盖同日更新的观测。

增长基线须在目标日或前一天，最新观测须在近一天且晚于基线。不会拿二十天前的值冒充今日增长。基线不够时仍展示明确标注的活跃热门列表；显式增长排序不伪造数值。

日/周/月历史需真实时间积累。采集是有界样本，不保证每个项目每天都有完整快照。

## 访问保护与缓存降级

同 IP、同操作组的每分钟上限：登录 10、feed 40、写操作 90、普通读 120。超过上限返回 429 和 `Retry-After`。计数桶最多 4096，过期回收，满桶时拒绝新来源。JSON 正文按字节有界读取，超限返回 413。

语言与分类的笛卡尔组合最多十六个，超限明确返回 `filterLimit`，不会默默截掉已选条件。可减少选择，或使用全部语言/全部分类降低回源扇出。

**入口限流是 Worker 实例内的轻量保护，不是全球严格配额**。多实例/不同 IP 各有计数，共享出口用户可能互相影响；不替代 WAF、DDoS 防护或容量规划。

公共 GitHub 回源：实例内最多六十四个不同查询，同查询合并；D1 四十五秒租约防止不同实例重复回源。锁被占用时用可用旧缓存，没有缓存返回 429，不无限轮询或重复打上游。

公共原始响应新鲜期十五分钟；配额不足或上游暂时失败时，允许最长二十四小时的已有公共缓存。五语言界面明确提示可能过时，保留原有趋势说明。降级多选/最新列表分页快照保存一分钟，推荐批次保存一小时以稳定当前分页。无匹配缓存就报错，不用演示或不相关数据冒充。

只允许公共服务端端点进入共享缓存，过滤私有仓库。身份、用户 Stars、画像、私人响应不进入共享回源缓存；账号缓存和游标继续按用户隔离。PAT 不写入服务端持久存储。

低配额写聚合告警；429 后按上游重试时间共享熔断，无提示时默认六十秒，最长一小时。它减少重复失败，不保证配额一直足够；Cron 和用户授权仍可能消耗各自额度。

## 配置专用采集 Token

在 GitHub 创建单独的公共采集只读 Token，设置到期时间。不要使用 GitHub CLI 登录凭据、个人 Star 写令牌或私库写权限 Token。

在本机交互运行，按提示输入：

```powershell
node --env-file=.env node_modules/wrangler/bin/wrangler.js secret put GITHUB_TOKEN
pnpm ops:status
```

Token 只进入 Cloudflare Secret，不放源码、命令参数或聊天。`tokenConfigured=true` 后还需观察真实采集成功；配置存在不代表令牌有效。此次没有替用户创建、复制或上传凭据。

## 本地归档脱敏日志

```powershell
pnpm logs:archive
```

默认目录 `D:\USER_TEMP\opencode\github-discover-logs`，用 `LOG_ARCHIVE_DIR` 可覆盖。只保存白名单应用字段和资源诊断，不转存请求头、完整 URL、任意异常字符串。

按 UTC 日及大小轮转，单文件最多 10MiB，保留十四天、最多四十份归档；只清理本工具命名规则下的旧文件，不删无关文件，不是无限永久保存。请限制目录的 Windows 访问权限。

进程退出、网络断开或 Tail 配额受限会造成缺失，不自动补齐历史日志。外部推送按用户选择未启用；需要主动查看 `pnpm ops:status` 或本地日志。

## 验收与发布边界

- 自动化覆盖回源合并、租约竞争/过期、旧缓存降级、真实日期、错误基线排除、采集重试/失败记录。
- 登录回归覆盖会话过期、PAT 缺失/撤销/错账号、OAuth 撤销/缺写权限、细粒度 PAT 写权限不足。失效授权不会删除收藏。
- `pnpm test:load:local` 只接受 localhost，总计二百请求、并发五；验证成功与限流，不是生产容量证明。
- UI 使用明确夹具；真实 OAuth 登录仍需用户验收，不声称模拟令牌等于真实授权。
- `pnpm release` 测试/构建/push后，应用增量迁移再部署。生产检查最多十九请求、串行：十首页、最多七趋势、两私有诊断。资源错误或 5xx 停止，不做生产压力测试。

`0003_operations.sql` 仅新增表。推送后部署失败不会自动回滚代码/数据库，也不会擅自丢弃用户数据。
