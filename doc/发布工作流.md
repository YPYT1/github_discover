# 一键推送与部署

提交已确认的修改后运行 `pnpm release`。该本地发布工作流依次运行测试、Lint、格式检查、OpenNext 构建与静态首页验证，随后推送当前分支到 origin，部署正式站，检查线上首页和日/周/月趋势及筛选。任一步失败即停止；推送成功而部署失败时不会自动撤销提交，可修复后重跑。

要求：GitHub 推送权限、Cloudflare Worker/D1 部署权限以及本机 `.env` 中的部署配置或已有 Wrangler 登录。不会自动提交/暂存文件，不会复制 OAuth/PAT 等应用凭证至 GitHub，也不会变更套餐。开始时工作区必须干净。

此命令是本地串行发布工作流，不是 GitHub Actions；未配置 GitHub Actions 仓库密钥。应用代码推送和部署使用同一构建版本。独立 demo 使用 `pnpm demo:deploy`，不参与正式站发布。

## 热门趋势

生产初始快照全部在 2026-10-09，无法计算过去一天/一周/一月的 Star 增长。每六小时 Cron 继续采样。完整历史优先；选中范围没有可用增长结果时，查询真实 GitHub 公共项目，使用 `pushed` 时间限定最近活动，按总 Star 提供备用列表。UI 明确标注不是增长榜；每个筛选组合最多 100 个候选，缓存十五分钟，分页稳定。语言/分类保留组内 OR、组间 AND，仍可能因严格筛选或 GitHub API 限额没有结果。

不创建过去日期的假快照。备用查询写入真实当前快照，有利于之后建立基线。显式在其他信息流选择增长排序时，仍要求真实历史，不偷偷替换为热度排序。
